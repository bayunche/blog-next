# 落樱轻声（blog-sakurairo）整站改造总方案

## 项目目标

从“主题展示型博客”升级为“对第一次访问者更友好、能持续引导阅读、能更好展示作者能力与内容价值的个人博客”。

这份方案基于以下页面与实现现状整理：
- 首页 `/`
- 文章列表 `/posts`
- 文章详情 `/posts/[id]`
- 关于页 `/about`
- 友链页 `/friends`
- 归档页 `/archives`
- 分类页 `/categories/[name]`
- 标签页 `/tags/[name]`

---

## 一、当前站点的核心问题

### 1. 气质有了，但“内容导航能力”偏弱
站点的视觉氛围、主题感和个性是成立的，但普通访客进入后，仍然需要花比较多时间才能理解：
- 这个博客主要写什么
- 我应该先看哪篇
- 作者擅长什么
- 有哪些内容是值得收藏的

### 2. 信息架构还比较“按功能分页面”，不够“按阅读任务组织”
当前页面基本都有，但更多像传统博客功能页：
- 首页
- 列表
- 正文
- 归档
- 标签
- 分类
- 关于
- 友链

对访客来说，真正的任务更像：
- 我想快速认识作者
- 我想找技术文章
- 我想看入门 / 系列 / 热门内容
- 我想继续往下看，不想每篇都重新找路

### 3. 内容数据质量影响了观感
当前站点最伤成品感的不是配色，而是数据呈现问题：
- `Uncategorized` 直接暴露
- 摘要里存在 Markdown / 代码块 / 图片语法残留
- 多处 `0 评论`
- 社交链接存在默认占位值
- About 页内容与博客真实定位有脱节
- 详情页暴露“编辑文章”入口
- 看板娘提示“资源未就绪，正在重试或等待网络...”会被用户看见

---

## 二、整站改造原则

### 必须有
1. 让访客 5 秒内知道你是谁、写什么、值不值得看
2. 让访客 15 秒内找到一篇想点开的文章
3. 让访客看完一篇后自然进入下一篇
4. 清理所有占位内容、默认值、后台感入口

### 应该有
1. 内容按“主题/系列/难度/代表作”组织，而不是只按时间排序
2. 页面文案统一：更像“个人技术博客”，少一些模板感
3. 每个页面都承担明确任务，不只是“这个路由存在”

### 加分项
1. 形成“作者品牌感”：你是谁、擅长什么、风格如何
2. 强化专题内容入口，例如 Java / Go / Electron / 前端
3. 增强可分享性：热门文章、代表作、About、RSS

## 三、建议的信息架构升级

## 1. 顶部导航建议
当前：
- 主页
- 朋友们
- 文章列表
- 关于/About

建议调整为：
- 首页
- 文章
- 专题
- 归档
- 关于
- 友链（可保留，但优先级低于“专题/归档”）

原因：
- “朋友们”对新访客不是高频任务
- “专题”比“友链”更能服务首次访问者
- “归档”是博客的经典信息入口，建议提升可见性

## 2. 首页首屏内容结构建议
建议首屏按四层信息组织：
1. 博客名
2. 一句话自我定位
3. 主要内容方向（2~4 个标签）
4. CTA 按钮（开始阅读 / 热门文章 / 关于我）

参考结构：
- 落樱轻声
- 记录 Java / Go / Electron / 前端开发中的学习、实战与踩坑
- `Java` `Go` `Electron` `性能优化`
- [从这里开始看] [查看最新文章] [关于我]

## 3. 新增“专题页”或“内容导航区”
即使不单独做路由，也建议在首页和文章列表页增加专题入口：
- Java 学习路线
- Go 入门笔记
- Electron 系列
- 前端性能优化
- 网络安全笔记

这样可以把零散文章组织成“能连续阅读的内容产品”。

## 四、整站统一问题清单

### 1. 分类默认值问题
代码中多个位置存在：
- `category || { name: 'Uncategorized' }`
- 分类页直接暴露 `Uncategorized`

建议：
- 后端或前端统一映射为中文：`未分类`
- 更进一步：尽量补齐真实分类，避免前台展示“未分类”

### 2. 摘要清洗不一致
首页用了 `stripMarkdown`，但：
- `/posts` 直接 `article.content.substring(0, 150)`
- `/categories/[name]` 直接 substring
- `/tags/[name]` 直接 substring

结果：
- 列表摘要暴露 Markdown 标记
- 暴露代码块、`![[Pasted image...]]`、标题符号、标签符号等

建议：
- 所有列表摘要统一改为 `stripMarkdown(content).slice(...)`
- 增加 `getArticleExcerpt()` 工具函数统一处理

### 3. 后台感入口暴露到访客态
详情页当前直接展示：
- `编辑文章`

建议：
- 仅登录管理员后显示
- 访客态完全隐藏

### 4. 占位社交链接问题
About 页当前社交链接为：
- github.com
- twitter.com
- t.me
- bilibili.com
- mailto:example@email.com

这是典型的“模板占位值”，对访客非常减分。

建议：
- 仅展示真实可访问的账号
- 没准备好的先隐藏
- 只保留 2~4 个高质量外链

### 5. 评论区冷启动感强
多处展示 `0 评论`。普通访客会潜意识感觉站点比较冷清。

建议：
- 列表页弱化评论数展示
- 当评论数为 0 时可不显示或替换为“欢迎留言”
- 正文页保留评论入口即可

### 6. 看板娘异常提示直接暴露
当前页面中存在：
- `看板娘资源未就绪，正在重试或等待网络...`

这会显得页面像“故障中”。

建议：
- 加载失败时静默降级
- 或仅在开发环境显示调试提示
- 生产环境对访客不显示错误文案

## 五、按优先级的落地顺序

## P0（必须先做）
1. 清理所有占位链接和错误提示
2. 隐藏“编辑文章”
3. 统一摘要清洗
4. 处理 `Uncategorized`
5. 首页首屏补充明确定位文案和阅读入口

## P1（强烈建议）
1. 文章列表增加分类/标签筛选
2. 文章详情页增加相关文章/上一篇下一篇
3. About 页改为真实作者介绍
4. 归档页增强跳转与检索能力

## P2（加分项）
1. 新增专题导航区
2. 做代表作 / 热门文章区
3. 为文章打“入门 / 实战 / 原理 / 踩坑”标记
4. 优化友链页，增加友链说明与筛选

---

## 六、建议你最终形成的页面体验

### 首页
像“博客门面 + 阅读入口”

### 文章列表
像“内容索引页”

### 文章详情
像“高质量阅读页 + 下一步引导页”

### About
像“作者名片页”

### 归档
像“按时间浏览的目录页”

### 分类 / 标签
像“专题聚合页”

### 友链
像“个人博客生态页”，而不是纯功能页
